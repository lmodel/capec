# Datasets

* [capec LinkML schema](capec-linkml-schema.md) - The LinkML model of CAPEC 3.9 under its XSD 3.5, `src/capec/schema/capec.yaml` (schema id `https://w3id.org/lmodel/capec`): an umbrella that holds only the tree root, `CapecAttackPatternCatalog`, over the modules `capec_entries` and `capec_core`.
* [Core module](core-module.md) - `src/capec/schema/capec_core.yaml`, the module with the value lists, text types and small records every CAPEC entry shares, and the abstract `CapecEntry`. It imports only `linkml:types`.
* [Entries module](entries-module.md) - `src/capec/schema/capec_entries.yaml`, the module with `CapecAttackPattern`, `CapecCategory` and `CapecView`, the records an attack pattern holds, and the value lists they use, such as `CapecAbstraction` and `CapecRelatedNature`.
* [Generated artefacts](generated-artefacts.md) - What `just gen-project` and `just gen-doc` generate from the capec schema: the projections in `project/`, the Python models in `src/capec/datamodel/`, and the merged schema in `docs/schema/`. None is edited by hand.
* [Example data](example-data.md) - The examples `tests/test_data.py` checks: valid examples of each class, a counter-example for each constraint, and catalogues that break the rules a JSON Schema cannot state, in `tests/data/valid/`, `invalid/` and `problem/invalid/`.
* [Exploiting Software: How to Break Code](example-external-reference.md) - REF-1 from the catalogue, written as a concept of type `CapecExternalReference` in the adapt copy's keys. It shows that the domain schema admits an external reference as a concept.
* [The schema's adapt copy](adapt-copy.md) - `.lokf/capec.yaml`, the copy `just lokf-adapt` writes from the schema so that it sits beside LOKF's `lokf.yaml`: rooted on `CapecEntry` and `CapecExternalReference`, with `ID` and `Reference_ID` dropped for LOKF's `id`, and five keys folded into `title` and `description`.
* [Copy of the upstream](upstream-copy.md) - `upstream/`: MITRE's CAPEC XSD 3.5 and catalogue 3.9, each byte for byte what MITRE serves and pinned by git object hash, with the Terms of Use beside them.
* [Mapping term list](mapping-term-list.md) - `tests/upstream/mapping-terms.txt`, the classes and properties of Dublin Core, schema.org, SKOS and the SEPSES CAPEC ontology, which `scripts/extract_mapping_terms.py` writes from each vocabulary's pinned file and `tests/test_mappings.py` holds each mapping to.
* [Neighbours' adapt copies](neighbour-copies.md) - The adapt copies of eleven released lmodel repositories (slsa, github-actions, in-toto, oscal, spdx, stix, attack, uco, cve, kev-catalog and nist-nvd) and of lmodel/cwe's branch in `tests/neighbours/`, each pinned by its SHA-256, against which `tests/test_schema_rules.py` holds this schema's copy apart and `tests/test_mappings.py` holds the mappings.
